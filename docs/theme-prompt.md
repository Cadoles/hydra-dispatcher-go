# Prompt de génération d'un thème

Le bloc ci-dessous fait générer par un assistant un thème des pages du dispatcher, contrat `api: 1` (`docs/themes.md`). Remplissez la ligne « Charte », joignez le logo et les polices s'il y en a, puis passez le résultat à `hydra-dispatcher theme check` : l'assistant doit l'avoir fait lui-même, et rendre un thème qui passe sans retouche.

```text
Tu crées un thème pour les pages du dispatcher Go d'Ory Hydra (hydra-dispatcher-go) : page de choix du mode de connexion, écran de consent, page d'erreur et confirmation de logout. Un thème est un répertoire que le dispatcher superpose, fichier par fichier, à son thème embarqué : ce que tu ne fournis pas reste celui par défaut.

Charte : <nom de l'établissement> ; couleurs <principale, texte, fond, alerte> ; police <nom et fichiers woff2, ou police système> ; logo <fichier SVG ou PNG> ; ton des textes <…> ; langues <fr, en, …>.

Rends un répertoire :
  theme.yaml                   name (un identifiant), version (libre, semver conseillé), api: 1 ; aucune autre clé
  static/theme.css             chargé après le CSS de base
  static/images/, static/fonts/, static/flags/<locale>.svg   facultatifs
  static/theme.js              seulement si indispensable ; les pages marchent sans JavaScript
  templates/…                  seulement les fichiers que tu changes, parmi layout.html.tmpl, select.html.tmpl, consent.html.tmpl, error.html.tmpl, logout.html.tmpl et partials/*.html.tmpl
  translations/<locale>.json   seulement les textes que tu changes, ou une locale entière ; la locale en minuscules (fr, de, pt-br)
et, à part, les lignes ui.csp_extra qu'il faut au déploiement (origine d'une police externe, sous la forme ui.csp_extra: {font-src: ["https://fonts.gstatic.com"]}), et le setting supported_locales s'il ajoute une locale : il est en base, écrit par la graine (bloc dispatcher: du fichier de configuration, supported_locales: [fr, en, es]) ou par l'administration.
Le dispatcher refuse un thème dont un fichier de templates/ ou de translations/ n'est pas l'un de ceux-là : n'y mets rien d'autre (pas de README, pas de sauvegarde). À la racine, il ne lit que theme.yaml.

Ordre de préférence :
1. theme.css seul, en redéfinissant les variables du CSS de base : --color-text (texte, titres compris), --color-muted (texte secondaire), --color-background (fond de la page), --color-surface (fond du cadre principal, main), --color-border, --color-accent (boutons, mode coché, liens de langue), --color-accent-text (texte sur l'accent), --color-alert (messages d'erreur), --radius, --space, --font. Le CSS de base n'a ni mode sombre ni style de focus propre (celui du navigateur). Classes du thème embarqué : .client, .logo, .lead, fieldset.flows, label.flow, .icon, .title, .description, .message, .scopes, .scope, .value, .audience, .trace, .locales, .flag, button.secondary.
2. Un partiel : partials/client_header.html.tmpl pour le logo, partials/flow_card.html.tmpl pour une carte de mode de connexion.
3. Un gabarit de page ou le layout, seulement si la charte l'exige. Une classe nouvelle n'a d'effet que si theme.css la définit.

Gabarits (html/template de Go, sans autre fonction que les siennes) :
- Chaque page est analysée avec layout.html.tmpl, partials/*.html.tmpl et son fichier (select, consent, error, logout). La page définit les blocs "title" et "content" ; le layout offre aussi "head", "header" et "footer", qu'une page peut redéfinir. Partiels : client_header, flow_card, locale_switcher, csrf. Un partiel que tu ajoutes est lu par toutes les pages. Chaque fichier de partiel commence par {{define "nom"}} et se termine par {{end}}. client_header et locale_switcher reçoivent les données de la page (.), et le layout les appelle dans "header" et "footer" sur toutes les pages, page d'erreur comprise, où .Client est vide ; flow_card reçoit un élément de .Flows ; csrf, les données de la page. Le titre h1 et le texte d'introduction sont dans chaque page, pas dans un partiel.
- Données : sur toutes les pages, .Locale ; .Locales, chacune avec .Code, .Label, .Action, .Flag (vide sans drapeau), .Current ; .Return ; .Error, nil hors erreur, avec .Code, .MessageKey, .TraceID, .Link (vide sans lui) et .SignOut (le logout d'Hydra, vide sauf sur certaines erreurs) ; sur la page de choix, .Error n'a que .MessageKey (mode refusé). Sur le choix, le consent et le logout : .Client (.Name, .LogoURI, .ClientURI, .PolicyURI, .TosURI, vides quand le client est inconnu) et .Form (.Action, .LoginChallenge, .ConsentChallenge, .LogoutChallenge, .CSRF, .Print). Sur le choix : .Flows (.ID, .Title, .Description, .IconURL, .Selected, vrai pour le dernier mode employé). Sur le consent : .Scopes (.Label, et .Claims avec .Label et .Value, vide sans consent.show_values) et .Audience (liste de textes). Sur le logout : .Logout avec .State (confirm, declined, in_progress ou already_out), .OtherSession et .Next ; hors de confirm, .Locales et .Form sont vides.
- Méthodes : {{.T "clé" args…}} (texte dans la locale de la page), {{.Asset "fichier"}} (URL hachée d'un fichier de static/, par son chemin sous static/ : "theme.css", "images/logo.svg" ; vide s'il n'existe pas, sans erreur : une faute de nom donne une URL vide), {{.Flag "fr"}}, {{.LocaleURL "en"}}. N'écris jamais une URL du dispatcher en dur (/static/…, /locale/…, /) : server.base_url peut porter un chemin. Passe par .Asset, .LocaleURL, .Form.Action et l'.Action de chaque locale. Dans theme.css, une police de static/fonts/ s'écrit url(fonts/…).
- Champs que lisent les gestionnaires, à garder tels quels, chacun entre les balises de son formulaire (le contrôle refuse un formulaire sans method="post", une action autre que {{.Form.Action}}, un champ hors du formulaire, un nom à la fois champ caché et bouton) :
  - choix : <form method="post" action="{{.Form.Action}}">, un radio name="flow" value="{{.ID}}" required par mode, avec {{if .Selected}} checked{{end}}, un champ caché login_challenge valant .Form.LoginChallenge, le partiel csrf, un bouton de validation (autofocus permis) ; sans .Flows, le texte choice.none et aucun formulaire ;
  - consent : <form method="post" action="{{.Form.Action}}">, un champ caché consent_challenge valant .Form.ConsentChallenge, le partiel csrf, {{if .Form.Print}}<input type="hidden" name="claims_print" value="{{.Form.Print}}">{{end}}, un bouton name="action" value="accept" et un bouton name="action" value="reject" (toute autre valeur refuse), aucun bouton avec autofocus ; sans .Scopes, le texte consent.nothing ;
  - logout, état confirm : <form method="post" action="{{.Form.Action}}">, un champ caché logout_challenge valant .Form.LogoutChallenge, le partiel csrf, un bouton name="action" value="accept" et un bouton name="action" value="reject" ; .OtherSession vrai : le texte logout.other_session en alerte ; état in_progress : le texte logout.in_progress et le lien {{.Logout.Next}} de texte logout.continue ; already_out et declined : leur texte ;
  - langue : <form method="post">, {{with .Return}}<input type="hidden" name="return" value="{{.}}">{{end}}, puis un bouton par locale avec formaction="{{.Action}}", aria-current="true" et disabled sur la locale courante ; le sélecteur n'apparaît qu'avec plus d'une locale ;
  - erreur : {{.T .Error.MessageKey}}, .Error.TraceID et .Error.Code, le lien .Error.Link s'il existe (texte error.back), le lien .Error.SignOut s'il existe (texte error.sign_out) ;
  - le partiel csrf : <input type="hidden" name="csrf_token" value="{{.Form.CSRF}}">.
- N'insère pas de HTML brut : tout est échappé, et une URL en javascript: ou data: devient #ZgotmplZ. Une image vient de static/images (par .Asset) ou d'une URL http(s), que la CSP permet sans ui.csp_extra (le logo d'un client). Aucun drapeau n'est embarqué : fournis static/flags/<locale>.svg pour chaque locale proposée, ou aucun, le sélecteur ne montrant alors que les noms.

CSP, que le thème ne peut pas lever : ni <script> sans src ni attribut on…, ni <style> ni attribut style="…", ni URL javascript: ; scripts, styles et polices viennent de static/ ; une origine externe (police, image) s'ajoute par ui.csp_extra. Les pages ne s'affichent jamais dans une iframe.

Traductions : JSON plat clé → texte, fusionné clé par clé avec les catalogues fr et en. Les textes par défaut sont sobres, au vouvoiement en français ; ne les réécris que si le ton de la charte l'exige. Tu peux ajouter tes propres clés, appelées par tes gabarits : chaque locale du thème doit alors les avoir. Une locale ajoutée a toutes les clés que les pages emploient, le contrôle refusant une clé manquante : choice.title, choice.client (%s : nom du client), choice.submit, choice.invalid, choice.none, consent.title, consent.intro (%s : nom du client), consent.other, consent.nothing, consent.audience, consent.accept, consent.reject, error.title, error.trace (%s : référence pour le support), error.back (lien vers le site de l'application), error.sign_out (lien de déconnexion de la session en cours), error.E1000 à error.E1008, logout.title, logout.intro, logout.accept, logout.reject, logout.declined, logout.other_session, logout.in_progress, logout.continue, logout.already_out, locale.label, locale.<code> (le nom de la locale dans sa propre langue, dans le catalogue de cette locale ; les autres catalogues ne l'emploient pas), scope.openid, scope.profile, scope.email, scope.address, scope.phone, scope.generic (%s : nom du scope), claim.sub, claim.name, claim.family_name, claim.given_name, claim.preferred_username, claim.locale, claim.email, claim.email_verified, claim.address, claim.phone_number, claim.phone_number_verified. Les textes sont du texte, pas du HTML ; garde chaque %s.
Sens des textes dont le nom ne suffit pas : choice.client, sous-titre qui prolonge le titre (« pour vous connecter à %s ») ; consent.other, le groupe des données transmises qui ne relèvent d'aucun scope demandé ; consent.audience, libellé de la liste des destinataires (des API) ; logout.title, le titre de la page, logout.intro, la question posée ; logout.other_session, alerte : la demande de déconnexion vise une autre session que celle ouverte dans ce navigateur, à refuser si l'utilisateur ne l'a pas faite ; logout.in_progress, une déconnexion déjà commencée, que logout.continue reprend. Codes d'erreur, un message distinct pour chacun : E1000, erreur inattendue, réessayer ; E1001, lien de connexion invalide ; E1002, connexion expirée ou déjà terminée, à reprendre depuis l'application ; E1003, la connexion ne correspond pas à la session en cours ; E1004, service d'authentification momentanément indisponible, réessayer ; E1005, mode de connexion mal configuré ; E1006, connexion non finalisée (un service consulté l'a refusée), réessayer ; E1007, la connexion n'a pas pu aboutir, à reprendre depuis l'application ; E1008, demande non vérifiée (venue d'un autre site), à reprendre depuis l'application.

Accessibilité : contraste AA, focus visible, libellé de chaque contrôle, aria-current de la locale courante gardé, role="alert" sur les messages d'erreur, page lisible sur mobile (360 px) comme sur ordinateur, sans JavaScript ; alt="" sur une image décorative.

Avant de rendre : lance `hydra-dispatcher theme check <répertoire>` et corrige jusqu'à ce qu'il passe ; donne sa sortie. Puis, pour chaque fichier, une ligne sur ce qu'il change.
```
